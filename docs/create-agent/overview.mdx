After [initial setup](/harness/initial-setup), build an agent in the chat UI composer (or via the [SDK](/api/overview)).

An agent is a saved combination of:

1. **Model** — which LLM runs the loop
2. **MCP servers** — which tools it can call
3. **Skills** — which procedures it can load
4. **Instructions** — the system prompt for this agent's role
5. **Configuration** — sandbox, tool approvals, ask-user-questions, generative UI

## Build it in the UI

1. Open TrueForge and use the composer to create or edit an agent.
2. **Select a model** from the providers you configured under Settings → Models. Switching it later is a one-click change — no new API keys in the agent definition.
3. **Attach connectors** (MCP servers) the agent should use. Prefer only the servers it needs.
4. **Attach skills** if the agent should follow specialized procedures (requires [sandbox](/sandbox) enabled on the agent).
5. Write focused **instructions** — role, audience, and behavior. Put long playbooks in skills, not the prompt.
6. **Save** the agent so it appears in the [Agent Library](/agent-library).

## Configure capabilities

Beyond model, tools, and skills, you can tune how the agent behaves at runtime. **Generative UI**, **Ask clarifying questions**, and **Dynamic sub-agents** are toggles in the composer's **Capabilities** tab — all on by default. **Tool approval** is a per-tool policy (below).

### Tool approval

Some actions — deploying, deleting data, sending refunds — shouldn't run without explicit consent. **Tool approval** (human in the loop) pauses the agent before a sensitive MCP tool call, shows the tool name and arguments, and resumes only after the user approves or denies. Safe read-only tools stay autonomous.

Approval policy is set **per MCP server**. The default gates write and destructive tools — anything the server doesn't mark read-only; you can also list specific tools or gate every tool ([`mcp_servers`](/create-agent/agent-spec#mcp_servers)).

<Frame caption="The chat UI pauses on a sensitive tool call with Allow / Deny.">
  <img src="/images/hitl.png" alt="Chat UI pausing on a tool call, showing the request payload with Allow and Deny buttons" />
</Frame>

Use approvals for state changes, irreversible actions, production impact, external communications, or expensive operations. Skip them for safe reads (list, fetch, search). Approval doesn't replace authorization — it only decides whether a pending call should proceed.

### Ask user questions

Agents often hit decision points they shouldn't guess — which environment to deploy to, which of several matches the user meant, or what an ambiguous required field should be. **Ask User Questions** pauses the agent, shows a multiple-choice prompt, and resumes with the chosen answer. It's on by default; toggle it in the composer's **Capabilities** tab.

<Frame caption="The chat UI renders the question and options as a selectable card.">
  <img src="/images/ask-user-questions.png" alt="Chat UI showing an agent question with multiple-choice options and a Submit button" />
</Frame>

Good for: choosing a target environment or account, disambiguating multiple matches, filling required fields the user didn't specify, or picking a strategy before a destructive step. Skip it when the agent can confidently infer the answer — over-asking turns the agent into a form.

### Generative UI

For dashboards, comparisons, and structured data, **Generative UI** lets the agent stream interactive components — charts, tables, cards, forms — that the chat UI renders as React. It's on by default; toggle it in the composer's **Capabilities** tab. The agent embeds a small OpenUI snippet in its response; the client renders real components as tokens stream in — no arbitrary code execution, only registered components.

<Frame caption="A Generative UI response with a chart rendered inline in chat.">
  <img src="/images/generative-ui.png" alt="Rendered Generative UI response with an inline bar chart comparing options" />
</Frame>

| Use case | What the agent renders |
| --- | --- |
| Dashboards | KPI cards, charts, comparison tables |
| Tables | Sortable logs, resources, result sets |
| Charts | Bar, line, pie patterns faster than prose |
| Forms | Guided inputs for the next action |

Skip it for short explanations, bullet lists, or code blocks where markdown is enough.

### Dynamic sub-agents

For multi-step work across several sources, the agent can delegate focused subtasks to parallel **subagents** and merge only their results — keeping its own context clean. On by default. See [Subagents](/key-features/subagents) for how it works.
