TrueForge works with the major model providers and any OpenAI-compatible endpoint. Provider credentials are configured once — in the UI under **Settings → Models** or via the settings API — and agents reference models by name. Agent definitions never contain API keys.

## Supported providers

| Provider type   | Notes                                                                  |
| --------------- | ---------------------------------------------------------------------- |
| `openai`        | OpenAI                                                                 |
| `anthropic`     | Anthropic                                                              |
| `google-gemini` | Google Gemini                                                          |
| `fireworks`     | Fireworks AI                                                           |
| `together`      | Together AI                                                            |
| `moonshot`      | Moonshot AI (Kimi)                                                     |
| `zai`           | Z.ai (GLM)                                                             |
| `alibaba`       | Alibaba (Qwen)                                                         |
| `custom`        | Any OpenAI-compatible endpoint — self-hosted models, gateways, proxies |

## Configuring a standard provider

Open **Settings → Models**, pick a provider, and paste your API key. Models from that provider become available immediately in the agent model selector.

## Where the model list comes from

The providers and models in **Settings → Models** come from a shipped catalog YAML on the server:

[`model-catalog.yaml`](https://github.com/truefoundry/trueforge/blob/main/packages/server/src/catalog/model-catalog.yaml)

That file lists the standard provider presets and model IDs. When you pick a provider in the UI, you paste your API key and TrueForge stores a configured provider — the catalog itself is never called with your credentials.

## Adding a custom provider

Use the `custom` provider type for vLLM, Ollama, a corporate gateway, or any other OpenAI-compatible API. Custom providers are not in the catalog — you add them yourself with a base URL, API key, and the model IDs you want exposed.

## Referencing a model in an agent

Models are addressed as `provider/model` in the agent spec:

```json
{
  "model": {
    "name": "anthropic/claude-sonnet-4-6",
    "params": {
      "max_tokens": 4096,
      "temperature": 0.2
    }
  }
}
```

`model.params` supports `max_tokens`, `temperature`, `top_p`, `top_k`, `parallel_tool_calls`, and `reasoning_effort` — plus any extra provider-specific parameters, which are passed through as-is. See the [agent spec reference](/api/agent-spec#model).

Switching models is a one-line change to the agent spec (or one click in the UI). No code edits, no new credentials.

<Tip>
  Token usage per model call is reported on every `model.message` event (`usage.input_tokens`, `usage.output_tokens`,
  and a breakdown of where input tokens went), and per-turn totals appear in `turn.done` metrics — so you can see
  exactly what a model choice costs before switching.
</Tip>

<Note>
  **Planned:** automatic model selection for different turns or subagents. Today each agent (and each subagent
  invocation) uses the model you configure. In the future, TrueForge will be able to pick among a set of models per
  turn or subagent based on task complexity, latency, and cost — without changing agent code.
</Note>
