## The Theme Object

The theme object lets you customize the appearance of the UI by passing design tokens that override component styles. You can also use it to override app-level CSS classes for broader layout and styling customizations.

```jsx App.jsx
type ThemeConfig = {
  ...
  tokens?: Partial<SemanticTokens>;
  icons?: IconMap;
  ...
};
```

## The Token Object

The theme object provides a flexible way to customize the colors and visual appearance of the Agent SDK. You can override individual design tokens to control the appearance of different UI elements, including the sidebar, page background, popups, buttons, input fields, and more.

Theme tokens can be configured independently for both light and dark modes, allowing you to create a consistent experience across different color schemes without having to override individual components manually.

The easiest way to explore and customize the theme is through our UI Config App. You can experiment with different color tokens and see your changes reflected in real time in the preview window. Once you’re happy with the theme, you can use the generated configuration in your application. [Visit Config App](https://ui.trueforge.dev/)

## Token naming

SemanticTokens keys map directly to kebab-cased CSS variables. For example, `primaryButtonBg` maps to `--primary-button-bg`, and `userMessageText` maps to `--user-message-text`. The only exception is `fontFamily`, which maps to the `--font-agent-ui` CSS variable.

Suppose your application uses a specific brand color for primary actions and a custom font. You can override the corresponding semantic tokens to apply your branding across the Agent SDK:
```ts
const theme = {
  tokens: {
    primaryButtonBg: "#635BFF",
    primaryButtonHover: "#5147E5",
    primaryButtonText: "#FFFFFF",
    fontFamily: "Inter, sans-serif",
    composerRadius: "12px",
  },
};
```
These tokens are automatically mapped to CSS variables:
```ts
--primary-button-bg
--primary-button-hover
--primary-button-text
--font-agent-ui
--composer-radius
```
This approach is useful when you want to customize the look and feel of the SDK while keeping the existing components, behavior, and layout intact. Instead of writing component-specific CSS overrides, you can change a small set of semantic tokens and have the changes applied consistently throughout the UI.

## Styling rendered content

`theme.classNames` (`ContentClassNames`) adds host CSS classes onto content renderers. Pass it through `theme` on `TrueforgeUI` (or `SlotsProvider`):

```tsx
<TrueforgeUI
  theme={{
    classNames: {
      markdown: "prose prose-sm",
      openui: { root: "my-openui" },
    },
  }}
  /* … */
/>
```

```ts
type ContentClassNames = {
  /** Root of the markdown renderer (joins `.aui-markdown`). */
  markdown?: string;
  /** Inline `` `code` `` spans inside markdown. */
  inlineCode?: string;
  syntaxHighlighter?: {
    root?: string; // joins `.aui-syntax-highlighter`
    pre?: string;
    code?: string;
    lineNumber?: string;
  };
  openui?: {
    root?: string; // joins `.aui-openui`
    scope?: string; // OpenUI theme scope (`.markdown-openui-scope`)
  };
  monaco?: {
    root?: string; // joins `.aui-monaco`
    editor?: string; // Monaco mount container
    /** Monaco theme name; when unset, follows light/dark mode. */
    monacoTheme?: string;
  };
};
```

For CSS-only adjustments you can instead target the stable class names directly: `.aui-markdown`, `.aui-syntax-highlighter`, `.aui-openui`, `.aui-monaco`.
