`layout` is required. Pass one of the built-in names or your own component.

<Tabs>
  <Tab title="sidebar">
    Full-page chat with a persistent thread list on the left. The default choice for a
    dedicated chat surface.

    ```tsx
    <TrueforgeUI server={server} layout="sidebar" />
    ```
  </Tab>
  <Tab title="drawer">
    Thread list collapses into an overlay drawer. Suited to narrower viewports.

    ```tsx
    <TrueforgeUI server={server} layout="drawer" />
    ```
  </Tab>
  <Tab title="dock">
    A panel pinned to the right edge, filling the available width up to a 400px cap. The side is
    not configurable.

    ```tsx
    <TrueforgeUI server={server} layout="dock" />
    ```
  </Tab>
  <Tab title="widget">
    Floating launcher that expands into a compact chat panel.

    ```tsx
    <TrueforgeUI server={server} layout="widget" />
    ```
  </Tab>
</Tabs>

Built-in layouts are code-split, so naming one does not pull the other three into your bundle.
A placeholder renders for the moment it takes to load.

`dock` and `widget` are compact layouts: rather than showing the thread list beside the
conversation, they stack the two and let the user switch between them from a history control.
`sidebar` and `drawer` keep the list available alongside the chat.

## Custom layouts

Pass a component instead of a string. It renders inside the full provider stack, so every
container hook and `useSlot` lookup works normally.

```tsx
import { Thread, ThreadListContainer, TrueforgeUI } from "@truefoundry/trueforge-ui";

function MyLayout() {
  return (
    <div className="flex h-full min-h-0">
      <aside className="w-72 shrink-0 border-r">
        <ThreadListContainer />
      </aside>
      <main className="min-h-0 flex-1">
        <Thread />
      </main>
    </div>
  );
}

<TrueforgeUI server={server} layout={MyLayout} />;
```

`Thread` is a convenience wrapper equal to
`<ThreadContainer composer={<ComposerContainer />} />`. Split them apart when you need the
composer somewhere other than directly beneath the transcript.

<Warning>
  The settings panel is part of the built-in layouts, so a custom layout does not get one. If
  you need settings, either stay on a built-in layout or build your own panel against the
  `catalog` server — see [Server](/ui-sdk/reference/server).
</Warning>

## Composing without TrueforgeUI

For maximum control, mount the providers yourself. Order matters — `SlotsProvider` must be
outside `TrueFoundryChatProvider`.

```tsx
<SlotsProvider overrides={overrides} theme={theme}>
  <ServerProvider server={server}>
    <ShellModeProvider agentConfig={{ mode: "AgentLibrary" }}>
      <TrueFoundryChatProvider server={server}>
        <MyLayout />
      </TrueFoundryChatProvider>
    </ShellModeProvider>
  </ServerProvider>
</SlotsProvider>
```

This path gives up the automatic runtime reset that `TrueforgeUI` performs when the selected
agent changes, so you become responsible for remounting `TrueFoundryChatProvider` — change its
`key` — at those moments.
