---
title: "Agent modes"
description: "Choose between a fixed agent, a library, a composer, or both."
---

This can be configured by using the `agentConfig` object.

```ts
type AgentConfig =
  | { mode: "SingleAgent"; name: string }
  | { mode: "AgentLibrary" }
  | { mode: "AgentComposer"; defaultAgentSpec?: AgentSpec }
  | { mode: "AgentLibraryWithComposer"; defaultAgentSpec?: AgentSpec };
```

The default is `{ mode: "AgentLibraryWithComposer" }`.

| Mode | Library | Composer | New chat |
| --- | --- | --- | --- |
| `SingleAgent` | — | — | Yes |
| `AgentLibrary` | Yes | — | No |
| `AgentComposer` | — | Yes | Yes |
| `AgentLibraryWithComposer (Default)` | Yes | Yes | Yes |

## Single Agent

All chats are done with one named agent which can be configured in `defaultAgentSpec`. All selection controls are hidden and the user cannot switch agents or open the composer.

## AgentLibrary

Users chat with agents from your agent library but cannot compose a new one. Note that “new chat” is disabled in this mode only.

<Frame>
  ![Agent Library 1](/images/agent-library-1.png "Agent Library 1")
</Frame>

## AgentComposer

Users compose/create a new agent by selecting models, skills, MCP servers and can save it back to the library.

<Frame>
  ![Agent Composer 1](/images/agent-composer-1.png "Agent Composer 1")
</Frame>

## AgentLibraryWithComposer

Users can pick an existing agent from the library or create a new one.

## Troubleshoot

<AccordionGroup>
  <Accordion title="defaultAgentSpec changes are not reflecting in UI">
    `defaultAgentSpec` changes are reflected in a new conversation rather than binding to the current one. Changing it does not alter the conversation on screen, and it does not apply on **clear chat** either. The new value is picked up when a **new chat** starts or when the app is refreshed.
  </Accordion>

  <Accordion title="Default model is showing as gpt-4.1">
    Always pass an explicit `defaultAgentSpec` in composer modes. Omitting it falls back to `{ model: { name: "openai-main/gpt-4.1" } }`, and requests fail if your backend does not expose a model under that exact name.
  </Accordion>
</AccordionGroup>
