## Run TrueForge

<Tabs>
  <Tab title="npx">
    Requires [Node.js](https://nodejs.org) 22.13 or newer. One command, no other infrastructure — data is stored in a local SQLite file:

    ```bash
    npx @truefoundry/trueforge
    ```

    Then open [http://localhost:8790](http://localhost:8790).

    | Configuration     | Default                    | Description                                     |
    | ----------------- | -------------------------- | ----------------------------------------------- |
    | `--port` / `PORT` | `8790`                     | HTTP port the server (UI + API) listens on.     |
    | `SQLITE_PATH`     | OS data dir                | Location of the SQLite database file.           |
    | `PUBLIC_BASE_URL` | `http://localhost:${PORT}` | Public origin, used for MCP OAuth callbacks.    |

  </Tab>
  <Tab title="Docker Compose">
    Runs the full production topology on your machine: the server (UI + API), Postgres, and Redis.

    ```bash
    git clone <REPO_URL> trueforge && cd trueforge   # TODO: repo URL
    cp packages/server/.env.example packages/server/.env
    docker compose up --build
    ```

    Then open [http://localhost:8791](http://localhost:8791).

    | Configuration                                         | Default                 | Description                                              |
    | ----------------------------------------------------- | ----------------------- | -------------------------------------------------------- |
    | `POSTGRES_USER` / `POSTGRES_PASSWORD` / `POSTGRES_DB` | from `.env`             | Postgres credentials, read from `packages/server/.env`.  |
    | `PUBLIC_BASE_URL`                                     | `http://localhost:8791` | Public origin, used for MCP OAuth callbacks.             |
    | Host ports                                            | `8791`, `5433`, `6380`  | App, Postgres, and Redis.                                |

  </Tab>
  <Tab title="Kubernetes (Helm)">
    The Helm chart deploys the server in distributed mode with bundled Postgres and Redis (or point it at your own). No values are required for a basic install:

    ```bash
    # TODO: replace <HELM_REPO> with the published Helm repo URL
    helm install truefoundry-utils oci://<HELM_REPO>/truefoundry-utils \
      --version <x.y.z>
    ```

    | Value                  | Default | Description                                                             |
    | ---------------------- | ------- | ------------------------------------------------------------------------ |
    | `server.publicBaseUrl` | `""`    | Public origin for MCP OAuth / OIDC callbacks; set once you expose the service. |
    | `replicaCount`         | `1`     | Number of server replicas (peered over Redis).                           |
    | `postgresql.enabled`   | `true`  | Bundle Postgres; set `false` + `externalPostgres.*` to bring your own.   |
    | `redis.enabled`        | `true`  | Bundle Redis; set `false` + `externalRedis.url` or `existingSecret`.     |

  </Tab>
</Tabs>

<Note>
  Standalone (`npx`) uses SQLite and needs no other services. Docker Compose and Kubernetes run the multi-replica
  topology: Postgres for storage and Redis for cross-replica peering. The agent features are identical in both.
</Note>

## Configure a model provider

TrueForge ships with a catalog of model providers. Configure one before your first chat:

<Steps>
  <Step title="Open Settings">
    In the UI, open **Settings → Models**.

    <Frame>
      <img src="/images/model-settings.png" alt="The Settings → Models page listing configured and available providers" />
    </Frame>
  </Step>
  <Step title="Pick a provider">
    Choose a provider from the catalog — OpenAI, Anthropic, Google Gemini, or an OpenAI-compatible endpoint — and paste
    your API key.

    <Frame>
      <img src="/images/model-configure.png" alt="Configuring a provider — pasting the API key and clicking Create" />
    </Frame>
  </Step>
  <Step title="Select a model">
    Back in the chat, pick a model. Models are addressed as `provider/model`, for example `anthropic/claude-sonnet-4-6`.

    <Frame>
      <img src="/images/model-pick.png" alt="Selecting a model from the chat composer's model picker" />
    </Frame>
  </Step>
</Steps>

Everything you can do in Settings is also available through the API — see `GET /api/v1/settings/model-providers/catalog` and `PUT /api/v1/settings/model-providers` in the interactive API docs at `/api/v1/docs`.

## Start chatting

Send your first message. Out of the box the agent supports multi-turn conversations with streaming. To give it more capabilities:

<Steps>
  <Step title="Connect tools">
    Add [MCP servers](/mcp-servers) under **Settings → Connectors**.

    <Frame>
      <img src="/images/getting-started-connectors.png" alt="The Connectors settings page listing connected and available MCP servers" />
    </Frame>
  </Step>
  <Step title="Enable the sandbox">
    Configure a [sandbox provider](/sandbox) under **Settings → Sandbox providers** so the agent can run code and use [skills](/skills).

    <Frame>
      <img src="/images/getting-started-sandbox.png" alt="The Sandbox providers settings page with Daytona connected" />
    </Frame>
  </Step>
  <Step title="Add skills">
    Register [git-backed skills](/skills) under **Settings → Skills**.

    <Frame>
      <img src="/images/getting-started-skills.png" alt="The Skills settings page with a selected skill" />
    </Frame>
  </Step>
</Steps>

## Call the API

Every conversation in the UI is a session in the API. Create one yourself:

```bash
curl -X POST http://localhost:8790/api/v1/sessions \
  -H 'Content-Type: application/json' \
  -d '{
    "agent": {
      "type": "value",
      "agent_spec": {
        "model": { "name": "anthropic/claude-sonnet-4-6" },
        "instructions": "You are a helpful assistant."
      }
    }
  }'
```

Then start a turn and stream events over SSE:

```bash
curl -N -X POST http://localhost:8790/api/v1/sessions/{session_id}/turns \
  -H 'Content-Type: application/json' \
  -d '{
    "input": [{ "type": "user.message", "content": "Hello!" }]
  }'
```

See the [API overview](/api/overview) for the full lifecycle — turn chaining, approvals, and event handling.
