<Info>
  **Released in TrueForge 0.185.0 — November 2026.** This is a breaking change for clients that answer tool approvals, agent questions, or MCP sign-ins.
</Info>

Before 0.185.0, a turn that needed something from the user (a tool approval, an answer to a question, or an MCP sign-in) **ended**. The stream closed with `turn.done`, and you answered by creating a **new turn** whose `input` carried the answer.

From 0.185.0, that turn **pauses** instead. It emits `turn.update` with `state.status: "paused"`, stays open, and waits. You send the answer **to the same turn**, and the same turn continues to `turn.done`. One user message is now one turn, however many times the agent stops to ask.

## Who is affected

| You use | What to do |
| --- | --- |
| The built-in TrueForge chat UI | Nothing. It already works with paused turns. |
| `@truefoundry/trueforge-sdk` or `trueforge-sdk` | Upgrade the SDK and follow [Migrate with the SDK](#migrate-with-the-sdk). |
| `@truefoundry/trueforge-ui` with your own server | Implement `sendTurnEvents` and paused turns. See [Server contract](/ui-sdk/setup-custom-servers/server-contract#answering-a-paused-turn) and [Bring your own server](/ui-sdk/setup-custom-servers/custom-server#pausing-for-the-user). |

## What changed

| Area | Before 0.185.0 | From 0.185.0 |
| --- | --- | --- |
| How a pause shows up | `turn.done` with `state.status: "done"`, `output: null`, and a non-empty `state.required_actions` | `turn.update` with `state.status: "paused"`; `turn.done` comes only when the turn really ends |
| How you answer | `POST /turns` (a new turn) with `user.tool_approval` / `user.tool_response` items in `input` | `POST /turns/{turn_id}/events` on the **same** turn |
| Resuming after MCP sign-in | `POST /turns` with empty or missing `input` | `POST /turns/{turn_id}/events` with `user.mcp_auth_continue` |
| `POST /turns` body | `input` optional; could contain `user.message`, `user.tool_approval`, `user.tool_response` | `input` required, at least one item, **`user.message` only**, non-empty `content` |
| `state.required_actions` on `turn.done` | Listed the pending actions | Always `[]` (kept for compatibility) |
| `state` when paused | `{ status: "paused", action_required_on_events: [...] }` | `{ status: "paused", metrics? }`. Pending actions are no longer listed in `state`. |
| SSE frame `id:` line | Per-stream sequence number | **Not sent.** Use the event's JSON `id`. |
| Subscribe resume cursor | `?after_sequence_number=N` | `?after_event_id=<event id>` or `?from_event_id=<event id>` |
| Cancel and new messages | Affected a running turn | Also affect a **paused** turn; a new message cancels it with `reason: "cancelled-for-next-turn"` |

### Read the stream and keep an event id

Iterate the stream directly and keep the **id of the last event** as your cursor. There is no sequence number any more. In Python, open streams with a `with` block so the connection closes when you stop reading.

<Tabs>
  <Tab title="Before">
<CodeGroup>
```typescript TypeScript wrap
const events = new Map<string, TrueForgeApi.TurnStreamingEvent>();
let turnId: string | undefined;
let lastSequenceNumber = 0;

const stream = await client.sessions.createTurnStream(session.id, {
  input: [{ type: 'user.message', content: 'Summarize the current state of open-source vector databases.' }],
});
for await (const { data: event, id } of stream.withMetadata()) {
  if (id != null) lastSequenceNumber = Number(id);
  if (event.type === 'turn.created') turnId = event.turnId;
  if (isEventDelta(event)) {
    const base = events.get(event.id);
    if (base) mergeEventDelta(base, event);
  } else {
    events.set(event.id, event);
  }
  if (event.type === 'turn.done') console.log('status:', event.state.status);
}
```

### Answer tool approvals on the same turn

Stop reading at the paused `turn.update`. Then **subscribe** from the last event id, **send** the approvals to the same turn with `createTurnEvents`, and **read** the subscription to see what the answer produced. Subscribe before you send so nothing the answer produces is missed.

<Tabs>
  <Tab title="Before">
<CodeGroup>
```typescript TypeScript wrap
const events = new Map<string, TrueForgeApi.TurnStreamingEvent>();
const pendingApprovals: TrueForgeApi.ToolApprovalRequiredEvent[] = [];

const stream = await client.sessions.createTurnStream(session.id, {
  input: [{ type: 'user.message', content: 'Restart the billing service.' }],
});
for await (const { data: event } of stream.withMetadata()) {
  if (isEventDelta(event)) {
    const base = events.get(event.id);
    if (base) mergeEventDelta(base, event);
  } else {
    events.set(event.id, event);
  }
  if (event.type === 'tool.approval_required') pendingApprovals.push(event);
}
// The stream ended with turn.done carrying required_actions.

const approvals: TrueForgeApi.UserToolApprovalEvent[] = [];
for (const pending of pendingApprovals) {

    if (msg?.type !== 'model.message') continue;
    const call = msg.toolCalls?.find(tc => tc.id === ref.id);
    if (!call) continue;
    console.log(`approve ${call.toolInfo.name}? args: ${call.function.arguments}`);
    approvals.push({
      type: 'user.tool_approval',
      threadId: pending.threadId,
      toolCallId: ref.id,

    });
  }
}

// Answer by creating a new turn whose input carries the approvals.
const resume = await client.sessions.createTurnStream(session.id, { input: approvals });
for await (const { data: event } of resume.withMetadata()) {
  console.log(event.type);
}
```

```python Python wrap
}
```

```typescript TypeScript wrap
for (const pending of pendingApprovals) {
  for (const ref of pending.toolCalls) {
    const msg = events.get(ref.sourceEventId);
    if (msg?.type !== 'model.message') continue;
```

### Continue after MCP sign-in

Resuming with an empty turn is no longer allowed. Once the user has signed in at each server's `authUrl`, send `user.mcp_auth_continue` to the paused turn.

```typescript TypeScript wrap
  input: [{ type: 'user.message', content: 'Summarize my latest GitHub issues.' }],
});
for await (const { data: event } of stream.withMetadata()) {
  if (event.type === 'mcp.auth_required') pendingAuth = event;

if (pendingAuth != null) {
```

### Resume a dropped stream

Resume from an event id instead of a sequence number, and resume `paused` turns as well as `running` ones. `fromEventId` replays starting **at** that event, so a reply that was mid-stream is rebuilt from its first delta; `afterEventId` replays only what comes after it.

<Tabs>
  <Tab title="Before">
<CodeGroup>
```typescript TypeScript wrap
// …after a disconnect, with session.id / turnId / lastSequenceNumber restored:
const { data: turn } = await client.sessions.getTurn(session.id, turnId!);
if (turn.state.status === 'running') {
  const resume = await client.sessions.subscribeToTurn(
    session.id,
    turnId!,
    { afterSequenceNumber: lastSequenceNumber },
    { timeoutInSeconds: 600 },
  );
  for await (const { data: event, id } of resume.withMetadata()) {
    if (id != null) lastSequenceNumber = Number(id);
    if (isEventDelta(event)) {
      const base = events.get(event.id);
      if (base) mergeEventDelta(base, event);
    } else {
      events.set(event.id, event);
    }
  }
} else {
  // Already finished: rebuild from the stored log (deltas already merged).
  for await (const event of await client.sessions.listTurnEvents(session.id, turnId!)) {
    events.set(event.id, event);
  }
}
```

```python Python wrap
# …after a disconnect, with session.id / turn_id / last_event_id restored:
turn = client.sessions.get_turn(session_id=session.data.id, turn_id=turn_id).data
if turn.state.status in ("running", "paused"):
    with client.sessions.subscribe_to_turn(
        session_id=session.data.id,
        turn_id=turn_id,
        from_event_id=last_event_id,
        request_options={"timeout": 600},
    ) as resume:
        for event in resume:
            index(event)
else:
    # Already finished: rebuild from the stored log (deltas already merged).
    for event in client.sessions.list_turn_events(session_id=session.data.id, turn_id=turn_id):
        events[event.id] = event
```
